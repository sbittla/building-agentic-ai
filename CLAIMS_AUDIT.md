# Volatile-claims audit ledger

This ledger records every claim in the book that can go stale: API, model, price, protocol, SDK, framework, benchmark, publication-date and adoption figures. Each row gives the manuscript location, the exact claim, the source it was checked against, the version tested, the result and who owns the next step. It answers the release review's request for a volatile-claims audit and covers Chapters 12–15, 20–24 and 27–30 first, plus the front matter, Appendices E and H, and the Chapter 16 and 25 claims the review named.

**Date checked:** 2026-10-13, against commit `c531ff0` (`book-v1.0.0-rc1` line). Line numbers come from the working tree at the time of writing. Other edits were in progress in `course/md/` (Chapters 2–14), so re-run the search if a line has moved.

**Results**
- **Verified:** a source seen on 2026-10-13 confirms the claim, and that source is cited. Repository facts were checked against `requirements.lock`, the `Dockerfile`, `course/code/`, `VERSION_MATRIX.md` and the solution logs, and `dev/check_references.py` and `dev/cost_model.py --check` both pass. Nothing was marked Verified from memory.
- **Needs correction:** the claim is wrong now. The row gives the correct value and its source. The editor changes the result to **Corrected** once the fix is merged and listed in `ERRATA.md` and `CHANGELOG.md`.
- **Unresolved:** no source confirmed or refuted the claim during this check. The author owns it.
- **Softened:** an unresolved claim whose book text was narrowed to what a source or the repository code confirms (release candidate 2).

**Before a patch release (`book-v1.0.x`)**
1. Re-check every row whose result or note mentions a model, price, beta header or retirement date. These change most often (see the Claude Haiku 4.5 retirement watch item).
2. Re-run `python3 dev/check_references.py` and `python3 dev/cost_model.py --check` after any change to `PRICES`, `VERSION_MATRIX.md` or the lock file.
3. Close each **Needs correction** row (fix the text, add an ERRATA entry, set the result to Corrected) and try again on each **Unresolved** row.
4. Update the date above, and add rows for any new volatile claim a patch introduces.

**Library versions seen on 2026-10-13** (the pins are still valid and resolvable; newer releases exist): `mcp` 2.2.0 → 2.3.0, `anthropic` 1.8.0 → 1.13.0, `claude-agent-sdk` 0.2.159 → 0.2.165, `a2a-sdk` 1.1.5 → 1.2.2, `langchain` 1.4.2 → 1.4.5, `langgraph` 1.2.12 → 1.2.15, `opentelemetry-sdk` 1.44.0 → 1.45.1, MCP Inspector 2.8.0 → 2.10.1 (PyPI JSON API and the npm registry).
