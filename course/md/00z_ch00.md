# Chapter 0: Foundations

The model is the clever part of an agent, yet most bugs you'll chase are ordinary. An API key pasted with a stray space. A JSON field that isn't there. A 429 from a server you called too fast. Every agent in this book is a Python program that sends JSON to a web API and acts on the JSON that comes back, so this chapter gives you those pieces one at a time: the terminal, Python, JSON, HTTP, API keys and Docker. If you've never touched any of them, good. Nothing here assumes you have.

**What you'll build:** a working course kit, your first model call, and small Python programs that read JSON, call a web API and handle errors.

**Prerequisites:** None. This chapter and the Python interlude after it are the book's **optional beginner path**.

## Learning objectives

By the end of this chapter you can:

- Open a terminal in the course container and move around with a few commands.
- Read and write the book's Python: values, lists, dictionaries, functions, loops and error handling.
- Convert between Python dictionaries and JSON, and read a JSON Schema.
- Call a web API, read its status code and use its JSON answer.
- Keep secrets such as API keys out of your code.
- Explain Docker, an image, a container and a volume in one sentence each.

## 0.1 The terminal and the course kit

A **terminal** is a window where you type commands instead of clicking: *PowerShell* or *Terminal* on Windows, *Terminal* on macOS, any terminal app on Linux. Move to the folder where you cloned or unzipped the course kit with `cd` ("change directory"):

```bash
cd D:\Learning\building-agentic-ai      # Windows: your own path
cd ~/building-agentic-ai                # macOS / Linux
```

Every command in this book starts with `./course.sh` (macOS and Linux) or `.\course.cmd` (Windows). It runs inside the kit's Docker container, so you never install Python yourself. Try these:

```bash
./course.sh help              # every course command
./course.sh list 0            # the exercises in this chapter
./course.sh shell             # open a terminal INSIDE the container
```

Inside the container, five commands are all you need:

Table: Five shell commands
| Command | What it does | Example |
| --- | --- | --- |
| `ls` | List files in the current folder | `ls notes` |
| `cd` | Change folder | `cd notes/work` (and `cd ..` to go back up) |
| `cat` | Print a file | `cat ch00_json.py` |
| `python` | Run a Python file | `python ch00_json.py` |
| `exit` | Leave the container shell | `exit` |

Your files live in the **workspace** folder next to `course.sh`. It's shared: a file you save there on your computer appears instantly inside the container, and the other way round. Any editor works; Visual Studio Code is a good free choice.

## 0.2 Python in one file

This file tours every Python feature the book uses. Run it with `./course.sh python ch00_python_tour.py`, then read the code next to the output.

Of everything in the tour, three ideas matter most for agents. **Dictionaries** (`{"id": "A1001", "total": 1225.0}`), collections of named values, are how all API data looks in Python; you read a field with `order["id"]`, or with `order.get("coupon", "none")` when it may be missing. **Functions** with type hints (`def total_with_tax(amount: float) -> float:`) become an agent's **tool** in Chapter 2 and an MCP tool in Chapter 12. And **`try` / `except`** catches errors, so instead of crashing, an agent can turn an error into text the model reads.

:::tip Reading errors
When Python fails, it prints a *traceback*, the calls that led to the error. Read it from the **bottom**: the last line says what went wrong (`KeyError: 'coupon'`), and the line above says where. After twenty years I still start there. Most beginner errors are a typo, a missing quote or wrong indentation, and that last line usually points straight at them.
:::

## 0.3 JSON and JSON Schema

**JSON** is text that looks almost exactly like Python dictionaries and lists. Programs use it to send each other data, and a model uses it to send tool requests to your code.

@@code ch00_json.py

`json.dumps` turns a dictionary into JSON text, and `json.loads` turns it back. **JSON Schema** is JSON that *describes* other JSON: which fields exist, their types and which are required. You'll write one for every tool in this book, so read the `schema` in the file carefully.

Table: JSON types and their Python equivalents
| JSON | Python |
| --- | --- |
| `{"a": 1}` object | `{"a": 1}` dict |
| `[1, 2]` array | `[1, 2]` list |
| `"text"` string | `"text"` str |
| `3`, `2.5` number | `3` int, `2.5` float |
| `true`, `false` | `True`, `False` |
| `null` | `None` |

## 0.4 Web APIs and HTTP

An **API** (application programming interface) lets one program ask another for something. Web APIs use **HTTP**, the protocol your browser uses. A request has a URL, a method (GET to read, POST to send) and optional **parameters** and **headers** (such as an API key). A response has a **status code** and a body, usually JSON.

@@code ch00_http.py

Table: HTTP status codes and what to do about them
| Status | Meaning | What to do |
| --- | --- | --- |
| 200–299 | Success | Read the JSON |
| 400–499 | Your request was wrong (400 bad input, 401 bad key, 404 not found, 429 too many requests) | Fix the request; for 429, wait and retry |
| 500–599 | The server had a problem | Retry later |

The Claude API is a web API too. From Chapter 1 on, the `anthropic` library sends these requests for you, but when it raises a `RateLimitError` you'll recognize the 429 underneath and know to wait and retry.

## 0.5 Secrets and environment variables

An **API key** is a password for an API. Anyone with your key can spend your money, so never write it in code or commit it to Git (the tool that tracks your code's history). Put it in an **environment variable** instead, a named value the operating system hands to every program it starts.

### Getting an API key

1. Create an account in the **Claude Console** (platform.claude.com). It's separate from a Claude.ai chat subscription: a Pro or Max plan doesn't include API use, which is billed by the token (a small chunk of text).
2. Under **Billing**, add a little prepaid credit, such as $10. The whole book on Claude Sonnet 5 costs about {{cost:learner}}, including reruns (Appendix E), so you can top up as you go.
3. Under **Limits**, set a **monthly spending limit**, your safety net if a loop runs away.
4. Under **API keys**, create a key and copy it. It's shown only once; if you lose it, make a new one.
5. In a terminal in the kit folder, run `./course.sh setup` (Windows: `.\course.cmd setup`) and paste the key when asked. The typing is hidden on purpose.
6. Run `./course.sh check --api`, which makes one tiny call to confirm the key works.

:::note What you should see
A list of checks, each with a ✔, ending with a line like `✔ API call  ready (claude-sonnet-5…)`. The model id after `ready` changes over time; what matters is the ✔. A ✘ names what's missing:
- **`API call  AuthenticationError`**: the key is wrong or has extra characters. Run `./course.sh setup` again with a new one.
- **`API call  PermissionDeniedError` or a credit message**: add prepaid credit (step 2).
- **`ANTHROPIC_API_KEY  missing`**: `.env` has no key. Run `./course.sh setup`.
- **`GitHub token  not set`** is fine; only exercises 14.3, 14.4 and Capstone 4 need it.
:::

The kit keeps your key in `.env` next to `course.sh`. Docker passes its values into the container, where your code reads them with `os.environ.get("ANTHROPIC_API_KEY")`, and `.gitignore` already keeps the file out of Git. `setup` writes it for you. If you edit it by hand, watch two traps: macOS Finder hides files whose names start with a dot (Cmd+Shift+. shows them), and Windows Notepad may save it as `.env.txt` unless you choose "All files".

:::warn Never paste an API key into code, a chat, or a screenshot
If a key leaks, delete it in the provider's console immediately and create a new one.
:::

### No budget? Use the free local model

If you'd rather not pay, you can run an open-source model, `qwen3.5:9b`, in Docker on your own computer. It's free, needs no key and runs almost every exercise, though it's slower and makes more mistakes than Claude. It needs 16 GB of RAM (32 GB is better), about 10 GB of disk and, optionally, a GPU.

1. Run `./course.sh setup` and choose option **2**, or put `PROVIDER=local` in `.env`.
2. Run `./course.sh local up`. It starts the model server and, the first time, downloads the model (about 6.6 GB). Add `--gpu` if you have an NVIDIA card.
3. Run `./course.sh check --api`. The reply now comes from `qwen3.5:9b` on your machine.

From then on, every `./course.sh` command uses the local model. `./course.sh local down` stops it and frees the memory; `PROVIDER=claude` switches back. Every exercise is labeled with the model it needs. Appendix H (also `LOCAL_MODEL.md` in the kit) covers Macs, speed tips and troubleshooting.

## 0.6 Docker in five minutes

Table: Docker terms and what they mean in the kit
| Word | Meaning | In the course kit |
| --- | --- | --- |
| Image | A frozen, ready-to-run operating system plus software | `building-agentic-ai:latest`, built once by `./course.sh build` |
| Container | A running copy of an image, isolated from your computer | Started by every `./course.sh` command, removed when it finishes |
| Volume | A folder shared between your computer and a container | Your `workspace` folder, seen as `/workspace` inside |
| Compose | A file describing containers and how they connect | `compose.yaml` in the kit |

So `./course.sh ex 4.2` means: *start a container from the kit's image with my workspace attached, run exercise 4.2 inside it, then remove the container.* Nothing but Docker is installed on your computer, and your files survive because they live in the workspace volume.

## Common mistakes

- Running commands from the wrong folder. Run `course.sh` from the kit folder (or with its full path).
- Editing the file in the kit's `course` folder instead of `workspace`. The `course` folder is the original baked into the image; your working files are in `workspace`.
- Mixing tabs and spaces in Python. Indent with four spaces; any editor can insert them for you.
- Putting an API key in code. Use `.env` and `os.environ`.

## Key takeaways

- The terminal runs commands; `./course.sh` runs them inside the course container.
- Dictionaries, lists, functions and `try`/`except` are the Python this book relies on.
- JSON is how programs exchange data; JSON Schema describes what valid JSON looks like.
- Web APIs return a status code and usually JSON; 4xx means fix your request, 5xx means retry.
- Secrets live in environment variables, never in code.
